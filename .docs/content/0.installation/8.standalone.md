# Standalone mode

The standalone mode runs ArmoniK.Core as a single .NET process, without Docker, Terraform or any external service. It is meant for development, demonstrations and small workloads on one machine.

The process contains:

- the control plane: the gRPC API used by the clients (tasks, sessions, results, events, ...);
- the compute plane: one or more compute slots, each running a polling agent;
- the queue, the database and the object storage.

Workers stay separate processes, so that they can be written in any language. Each compute slot is connected to one worker.

## Run it

Only the [.NET SDK](https://dotnet.microsoft.com/en-us/) >= 10.0 is required. All the dependencies come from the NuGet restore.

```shell
git clone https://github.com/aneoconsulting/ArmoniK.Core.git
cd ArmoniK.Core/Standalone/src
dotnet run
```

By default, the gRPC API listens on `localhost:5001` (HTTP/2 without TLS), and gRPC-Web and the health checks (`/startup`, `/liveness`, `/readiness`) on `localhost:5002` (HTTP/1.1). One compute slot is started, which waits for its worker.

## Start the workers

Each slot waits until its worker listens on the worker address, then starts its polling agent. The worker connects back to the agent address of the slot. With the default configuration, the addresses of slot `N` are Unix domain sockets in the data folder: `data/slotN/worker.sock` and `data/slotN/agent.sock`, relative to the current directory of the standalone process.

For instance, to run the HtcMock worker of the repository for slot 0:

```shell
cd ArmoniK.Core/Tests/HtcMock/Server/src
ComputePlane__WorkerChannel__Address=<data folder>/slot0/worker.sock \
ComputePlane__WorkerChannel__SocketType=UnixDomainSocket \
ComputePlane__AgentChannel__Address=<data folder>/slot0/agent.sock \
ComputePlane__AgentChannel__SocketType=UnixDomainSocket \
dotnet run
```

If a worker stops or becomes unreachable, the polling agent of its slot stops, as it does in a deployment. The standalone process then plays the role of the orchestrator: it creates a new agent for the slot, which waits for the worker again.

## Run a client

Clients connect to `http://localhost:5001`. For instance, with the HtcMock client of the repository:

```shell
cd ArmoniK.Core/Tests/HtcMock/Client/src
GrpcClient__Endpoint=http://localhost:5001 HtcMock__NTasks=100 dotnet run
```

The default partition is `default`: tasks submitted without a partition go to it.

## Configuration

The configuration is read from `appsettings.json`, environment variables and the command line, as for the other services. The options of the standalone host are in the `Standalone` section:

| Option | Default | Description |
|---|---|---|
| `Slots` | `1` | Number of compute slots, each connected to one worker |
| `DataFolder` | `data` | Folder of the object storage, of the caches of the slots and of their sockets |
| `GrpcPort` | `5001` | Port of the gRPC API (HTTP/2) |
| `HttpPort` | `5002` | Port of gRPC-Web and of the health checks (HTTP/1.1) |
| `ListenAnyIP` | `false` | Listen on all the network interfaces instead of the local machine only |
| `SocketType` | `UnixDomainSocket` | Type of the worker and agent channels: `UnixDomainSocket` or `Tcp` |
| `WorkerAddress` | `{data}/slot{slot}/worker.sock` | Address of the worker of a slot: a socket path, or a URI with `Tcp` |
| `AgentAddress` | `{data}/slot{slot}/agent.sock` | Address of the agent of a slot: a socket path, or a URI with `Tcp` |

In the addresses, `{data}` is replaced by the absolute path of the data folder, and `{slot}` by the index of the slot. For instance, with TCP channels: `Standalone__SocketType=Tcp`, `Standalone__WorkerAddress=http://localhost:1{slot}080` and `Standalone__AgentAddress=http://localhost:1{slot}081`.

The other sections (`Pollster`, `Submitter`, `InitWorker`, `InitServices`, ...) have the same meaning as for the polling agent and the submitter. The defaults of the standalone host set the partition `default`, and let a slot wait up to one hour for its worker (`InitWorker`).

## Limits

- **No persistence of the metadata.** The database is in memory: a restart loses the sessions, tasks and results. The object storage is on disk (in `<data folder>/objects`), but its files cannot be used without the metadata.
- **No authentication.** Authentication and authorization are disabled by default. This is why the API only listens on the local machine unless `ListenAnyIP` is set.
- **Socket paths.** Unix domain socket paths are limited to about 100 characters. With a long data folder path, set `WorkerAddress` and `AgentAddress` to shorter paths, or use TCP channels.
- **Single process.** A crash of the standalone process stops the whole ArmoniK, and all the writes of a table are serialised by one lock.
